# Beacon mobile app

Expo (SDK 57) app for iOS and Android, built with Expo Router and Supabase. The backend
contract it implements is `../docs/API_CONTRACT.md`.

## Setup

```bash
cd mobile
npm install
cp .env.example .env   # then fill in the values
```

| Variable | Purpose |
|---|---|
| `EXPO_PUBLIC_SUPABASE_URL` | Supabase project URL |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon (public) key. Never use the service role key. |
| `GOOGLE_MAPS_ANDROID_API_KEY` | Optional. Maps SDK for Android key. Without it, Explore shows the list view only on Android. |

`.env` is git-ignored. For EAS builds, add the same variables as EAS environment variables
(`npx eas-cli@latest env:create`) for the `development`, `preview` and `production` environments.

## Run

```bash
npx expo start            # Expo Go or a development build
npx expo start --clear    # after changing .env
```

The app uses only modules available in Expo Go, so it runs there for quick checks. For a
build that matches the store binary, create a development build:

```bash
npx eas-cli@latest build --profile development --platform ios      # or android
```

## Checks

```bash
npx tsc --noEmit
npx expo-doctor
npx expo export --platform ios
npx expo export --platform android
```

## Build and submit

```bash
npx eas-cli@latest login
npx eas-cli@latest build --profile production --platform ios
npx eas-cli@latest build --profile production --platform android
npx eas-cli@latest submit --profile production --platform ios
npx eas-cli@latest submit --profile production --platform android
```

Build numbers are managed remotely by EAS (`appVersionSource: remote`) and auto-increment
on production builds. Bump the marketing version in `app.config.ts` for each release.

## Configuration notes

- Bundle identifier and Android package: `BUNDLE_ID` at the top of `app.config.ts`.
- Location is foreground only. There are no "Always" location keys, and background
  location, camera and microphone permissions are blocked on Android.
- The iOS privacy manifest (required-reason APIs and collected data types) lives in
  `app.config.ts` under `ios.privacyManifests`.
- Legal and support URLs are in `extra.legal` in `app.config.ts`.
- Icons and splash are generated by `scripts/generate_assets.py` (needs Pillow):
  `npm run assets`.

## Structure

```
src/
  app/          Expo Router screens: (auth), (tabs), game/, group/, report, join-code, blocked
  api/          Supabase RPC and table access, one module per area
  components/   Shared UI (buttons, fields, cards, map, chat)
  constants/    Contract enums, labels, supported cities
  context/      Auth session provider
  hooks/        Data loading, device location, chat realtime
  lib/          Supabase client, env, formatting, links, validation
  theme.ts      Colours, spacing, type scale
```
